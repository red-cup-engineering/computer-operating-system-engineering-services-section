# Native node-job parameter realization

LAGOON's existing enterprise-deployment constructor binds the target's explicit job parameter value to the same Guix output that supplies its programs. The existing Code node-job-service owns declaration reading, schedules, receipts and local execution; Systems computer-system-engine/rpc/node-job-operations composes it with operation messages and findings. Generic Operations owns the parameterization descriptors, and Group/machine data supplies law, selected deployment records and scope terms.

The #:node-job-instance selection requires path, module, export and deployment-records-pointer. The pointer names an authored parameterData value in the raw host instance, normally /parameterData/nodeJobDeploymentRecords, shaped as {law, deploymentRecords:[{deployment,host,scope,jobConfiguration}]}. Records contain only the target's selected local job configurations, with distinct deployment names; the set is bounded to 100. Host is provenance/release metadata and grants no remote dispatch authority. Scope contains at most 64 unique bounded terms; an empty scope explicitly leaves ownership unknown.

Both operation and schedule Generic Operations descriptors bind that same instance pointer. Each parameter is admitted against its digest-bound Engineering Data model. The constructor first reads the full instance and its optional capability profile through MetroPlat's existing readInstanceDefinition API, using confined output-relative regular files and the original raw-host byte snapshot. It verifies that the selected parameter value is actually authored by the raw host, then derives the whole composed declaration. Profile-owned source arrays are admitted uniformly; profiles cannot supply target parameterData.

Each jobConfiguration supplies authored relative jobsDirectory, absolute persistent stateRoot, and unitPrefix. runtimeRoot and artifact must each be exactly {release}; only those two fields are projected to the actual Guix builder output. Every unrelated value remains unchanged. All operation and schedule parameterizations are resolved through the same Code read port before any job provider import; exactly one selected operation and schedule must bind the complete projected value. The existing nodeJobsAt reader then receives every configuration. This constructor never runs jobs, prechecks, network ports, systemd commands or host state writers.

The output serializes only the raw host declaration with its projected parameterData overlay, preserving shared-profile indirection. Exact original raw-host UTF-8 bytes remain at .guix-systemd/source-declarations/<instance-path>. Shared profile and immutable Group source records remain unchanged. Redirected paths, malformed or conflicting bindings, unresolved references and repeated source-custody writes refuse. Ordinary and first-cutover outputs each bind their own artifact coordinates while preserving the target's persistent state and unit identities.

RPC request input can select an installed deployment and job, never supply instance, command, runtime, artifact, scope, state or credentials. Execution roles and office powers retain their separate authorities. Source qualification covers Data models, actual provider interfaces, declared dependencies, native projection and byte custody; complete shared-runtime closure, both target/variant fabrication, useful operation and activation remain receiving obligations.
